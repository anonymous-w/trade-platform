# 通知中心

右上角铃铛显示个人未读数量（超过 99 显示 99+）。点击打开下拉面板，按新到旧展示事件类型、摘要、时间与已读状态。点击单条设为已读，「すべて既読」全部已读；列表支持滚动和「以前の通知を表示」。点击外部关闭。沿用现有日文界面。

## 触发与权限

- Excel 上传并成功预览：文件上传通知，明确尚未保存。相同用户重复预览相同文件只记录一次。
- Excel 确认保存、CSV 导入：提交成功才记录行数通知，与业务数据使用同一数据库事务。
- 上述操作失败：回滚后独立记录失败通知，保留原有页面错误反馈。拒绝认证或权限的请求不产生业务通知。服务器不可达或数据库不可写时无法保证保存通知。
- PDF 上传继续默认暂停；若以后启用，文档入库和上传通知使用同一事务，失败清理临时文件。
- 仅向操作本人发送；管理员也不能读取或修改其他用户的通知。暂不广播给所有人。
- 已定义 DATA_UPDATE / DATA_DELETE 类型，但当前业务没有修改、删除接口，因此没有虚构对应事件。新增这些业务入口时，须在同一业务事务内调用 NotificationService.record，并使用稳定的事件键。
- 不追溯补造升级前操作。首次安装通知表为空，未来真实操作才产生记录。通知不替代完整审计日志。

## 存储与接口

Flyway V4 新增 t_notification；用户外键、收件人+事件键唯一约束、历史及未读索引。成功事件按文件摘要或业务 ID 去重；每次真实失败请求独立计为一次操作。没有自动删除历史通知。

| API | 用途 |
| --- | --- |
| GET /api/notifications?size=20&before=ID | 游标分页，最多 100 条，返回 rows/hasMore/unreadCount |
| GET /api/notifications/unread-count | 当前登录用户未读数 |
| POST /api/notifications/{id}/read | 幂等已读，不存在或他人的 ID 返回 404 |
| POST /api/notifications/read-all | 只标记本人请求执行时的未读通知 |

所有接口沿用会话认证，写请求需要 CSRF。客户端无法指定收件人，也没有创建通知的公共接口。标题和摘要按普通文本渲染，不使用 HTML。

前端每 30 秒查询未读数；页面隐藏时暂停，恢复可见时同步。当前页面业务操作完成后额外触发一次查询；这只是刷新信号，通知内容仍由后端生成。面板打开时读取最新历史。组件卸载时清理定时器和事件监听。

## 验证

前后端构建及现有 Java 测试通过。scripts/tests/notification_regression.py 只能用于 localhost:8089 的 trade-notification-test 隔离栈，使用合成 XLSX/CSV 和临时账户。30 项检查覆盖真实触发、权限隔离、CSRF、并发去重、业务回滚、失败通知、游标分页、重复已读、全部已读及重新登录后的持久化。浏览器验证角标、单条已读、全部已读、滚动历史、刷新、点击外部关闭与轮询。

部署前备份数据库。V4 仅新增通知表，不修改现有业务表；回退应用代码可保留通知表，不要删除数据卷。真实资料、环境密码和备份不得提交 Git。

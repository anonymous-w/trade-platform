# 期限管理表导入（第一阶段）

管理员进入「データ取込み」→「期限管理表」，选择包含「期限管理表」工作表的原始 Excel（.xlsx / .xls，最多 10 MB），点击解析预览。无需单独导出工作表。

确认数量、原文和警告后，为每条记录选择追加、更新或跳过，勾选已确认并执行导入。已有记录默认跳过；重复提交同一次确认不会重复新增。若预览后数据已被修改，需重新预览。

导入后在「販売管理」的「契約・商品（期限管理表）」和「5年間監視」的期限管理表标签中查询。两者使用同一许可记录 ID 和数据库 API，详情可以互相跳转。原来的订单、监视及包装资料入口保留在其他标签中。

## 解析规则

识别契約番号、商品名、型番、輸出許可番号、役務許可番号、许可日期、有效期限、安装日期确认、报告提交期限、B/L 日期、一年目至五年目、担当者、責任者、条件内容。支持多行表头、全角文字、合并记录块和 Excel 数值日期；空白编号块不作为业务记录。条件内容按合同与出口许可匹配「条件内容」工作表。

年度主行日期保存为来源期限；只有明确的「確認完了予定日」「確認完了日」才分别识别为计划、完成日期。没有标签的补充日期保留原文并提示核实，不推断完成状态。多个相冲突的日期也不强行选取。公式不执行，保留公式文本并提示。

保留原始单元格、合并信息、原始附件及逐行导入日志。未提供的客户、金额等不生成数据。监视状态显示「要確認」，次回確認日不自动推算，期限提醒及状态计算需另行确认业务规则。

## 数据结构和重复处理

V5 新增 t_deadline_contract、t_deadline_equipment、t_deadline_permit、t_deadline_year、t_deadline_import、t_deadline_import_row 六张表，不改变既有业务表。

合同、设备、许可和年度均使用内部主键与外键。匹配键包含合同编号、商品、型号和两种许可编号，不只使用合同编号。唯一匹配的合同/设备组合可以关联多个许可；存在歧义时拒绝自动合并。不同设备目前分别创建合同父记录，不仅凭合同编号自动合并；后续确认业务唯一标识后可扩展关联维护。

标识字段发生变化会作为新候选记录，需人工核对，不会自动认定为原记录的修改。更新只改变来源数据，保留独立的 manual_* 监视字段；第一阶段尚不提供手工监视维护界面。

确认导入使用事务、数据库锁、版本校验和提交指纹。失败时业务及导入历史全部回滚；成功提交保存原始附件（数据库 BYTEA）和日志。管理员可导入，已登录用户按现有系统共享业务数据权限查询；通知只发送给操作者。

## 验证

Java 解析测试涵盖 xls/xlsx、合并块、日期、年度标签、条件关联和错误文件。真实业务工作簿仅在隔离环境作为本地测试夹具，未提交到代码仓库。

隔离环境通过 47 项接口回归检查，覆盖预览不落业务库、确认、并发防重、更新/跳过、保留手工字段、搜索分页、重新登录、附件原文及权限。另验证同一设备多许可关联和晚期数据库异常的事务回滚。前端通过 vue-tsc 与 Vite 构建；销售/监视详情关联已进行浏览器检查。

回归脚本 scripts/tests/deadline_regression.py 只能在独立的 trade-deadline-test / 8089 测试环境运行，不能在日常业务数据库运行。真实 Excel 不随仓库分发。

# 包装集计 Excel 导入变更记录

## 兼容性结论

旧接口只接受固定 18 列 CSV（单出口、单设备、单发票、单箱型配置，最多 300 行），不能直接接受提供的实际 XLSX。真实文件包含合并单元格、多设备、分解部件、列布局变化、保存的公式结果及不同集装箱写法；缺失客户、发票号与业务日期，不能凭空构造完整出口业务。

按照用户选择，本次实现原始包装资料的预览、确认保存和查询，不将其转成正式出口单。已有业务记录与原始资料分开管理，后续补齐信息和确认映射后才能生成正式业务数据。

## 实现

- 新增 `PackingWorkbookParser`，通过 Apache POI 5.5.1 读取单工作表、固定表头的 XLSX。校验大小、行数、列范围、合并区域、ZIP 展开大小，拒绝非匹配文件。
- B 契约、D/E 设备/型号等文字只在明确合并范围内继承；不对空白行无限向下填充。支持 D:E 合并、F 型号、G 部件的合同段变体，明确的 G/H 编号与数量对调会提示核对。
- 保存原始数值字符和原有精度。界面显示限制有效数字以避免 Excel 浮点尾数，原文详情保留原始保存值。共享数值不重复复制，疑似单位或体积差异只提示、不擅自修正。
- 不重新计算公式、不访问外部工作簿。设备信息中的外部引用保存值不作为确认信息；原公式、保存值、合并范围仍可查阅。
- 集装箱与港口按原文保存，不将不规范的箱型名称、无数量记载或航空运输条件猜成集装箱实绩。
- 预览不写库；确认保存必须携带文件摘要并确认原资料性质。全部记录在一个事务中保存，异常回滚整批。文件摘要和解析内容摘要双重去重，数据库唯一约束处理并发重复。
- 新增 V3 两张来源表，保留批次、导入人、文件/内容摘要、可检索字段、JSONB 数值、来源与核对项。未改写已应用的 V1/V2。
- 页面新增 Excel 预览、疑点查看、原文对照、确认保存、历史批次选择、合同/设备/型号/部件搜索、分页和疑点筛选。旧 CSV 功能折叠保留。
- 暂停 PDF 新上传（UI 移除，后端默认返回 410），既有 PDF 读取、下载、打印继续保留。

## 适用边界

这是指定包装集计格式的来源资料导入器，不是任意 Excel 的通用识别器。字段变体会标为要确认，不代表自动匹配准确性经过业务确认。数式使用 Excel 上次保存的结果，可能不是最新计算值。缺失设备名称、未知单位、体积差异、共享数量、外部引用或不明确集装箱不进行自动业务修复。

每个预览标签展示前 100 行；确认后保存全部行，查询每页 20 行，API 每页上限 100。历史入口显示最近 50 批。同内容重复被拒绝，修改过业务内容的文件会成为新批次；批次之间的合同重叠不自动合并，不应据此直接累加统计。当前没有原资料在线编辑或正式出口转单流程。

## 验证方式

- Java 单元测试包含生成的合并单元格、变化布局、共享数量、PALLET、浮点精度、公式缓存、外部引用、损坏文件、表头不匹配和上限案例。真实 Excel 只通过本地 `PACKING_TEST_FILE` 挂载读取，不进入 Git 仓库。
- `scripts/tests/packing_import_regression.py` 只用于 8089 的 `trade-platform-excel-test` 隔离数据库。检查匿名/普通用户权限、预览无写入、摘要变化拒绝、确认必填、数据库中途失败整批回滚、并发重复、语义重复、全量分页、检索、疑点筛选、原始数字逐格核对及退出。
- `scripts/tests/http_regression.py` 保留原有登录、权限、CSV、查询、退出、锁定回归检查，PDF 新上传预期改为 410。
- 单元测试使用 Docker Maven Java 21；前端使用 Docker Node 22 执行 TypeScript 检查与 Vite 构建。

## 完成结果（2026-10-18 本机）

- 真实工作表共 151 个合同号、2,718 行（Excel 5–2722 行），其中 1,117 行带核对提示。核对提示包含版式变体、集装箱原文、缺失或不一致信息，不等同于错误行数。
- 独立测试库完成全量保存、分页与查询，13,465 个尺寸/重量/体积数值逐格核对一致；数据库中途故障整批回滚、并发重复、同内容改名/重新压缩重复、权限和退出检查通过。
- 浏览器确认登录、文件选择、预览、重复提示和禁用保存按钮、合同查询、原文/疑点弹窗、固定退出入口。
- 本地 8088 系统已更新，Flyway V1/V2/V3 均成功。管理员确认后的实际文件保存为 batch_id=1，共 2,718 行；正式业务仍为 73 笔出口、32 笔销售、32 份文档、1 个原有用户，所有已有 PDF 读取成功。
- 来源数据未生成虚构客户/发票，也未加入正式集装箱实绩；没有覆盖现有业务记录。源码变更已放到本地 v0.2 项目。


## 管理检索整合（后续更新）

原资料接入輸出管理与コンテナ実績的 Excel取込資料标签。没有正式记录时默认显示原资料，正式列表保留在另一标签。检索跨所有批次，支持关键词及型号、集装箱原文、港口、疑点组合条件，并显示来源文件和行号。本次无需迁移或重新导入，不生成虚构业务字段。

用户清空演示数据后自行导入的 2,718 行原资料保留；上节 73 笔出口等数字是此前测试的历史快照，不代表当前数据。

前后端构建通过。隔离库恢复真实数据并加入第二个合成批次，29 项接口检查通过（权限、跨批次、分页、组合条件、通配符、参数校验、退出）。浏览器验证默认标签、NX76 的 7 行结果、原文来源、正式列表切换及集装箱组合筛选。脚本 scripts/tests/management_search_regression.py 仅指向 8089 隔离环境。
